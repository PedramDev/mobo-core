# Mobo Core 10.33.87 — Canonical Source-Hash Contract Repair

Mobo Product/Variation source hashes are generated by Product Sync with `md5()`, so their canonical persisted representation is 32 lowercase hexadecimal characters. 10.33.87 repairs a Custom Storage contract mismatch introduced during the storage rollout where mirror/repository/parity/read layers accepted only 64-hex hashes.

## Changes

- Adds `Mobo_Core_Source_Hash_Policy` as the single 32-hex normalization contract.
- Product/Variant Custom repositories, Storage Bridge, identity/state parity, primary state reads, and source-hash write suppression all delegate to the same policy.
- Valid 32-hex source hashes no longer collapse to empty Custom state.
- Commit-group hash suppression remains Custom-first and fail-closed.
- `mobo_sync_incomplete`, REST metadata writes, add metadata, and delete metadata remain Legacy-authoritative.

## Rollout

This is a correctness repair for the existing source-hash suppression stage. It does not advance retirement to `mobo_sync_incomplete`; that transition remains blocked until this repaired hash contract passes FAST and full release-gate evidence.
