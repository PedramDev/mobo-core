# Mobo Core 10.31.98

## کنترل کش آرشیو و شروع دستی Sync/Repair

این نسخه دو رفتار پرهزینه را به تصمیم صریح مدیر سایت منتقل می‌کند.

### تغییرات

- گزینه جدید `mobo_core_cache_purge_archives_on_product_update` به تب «بروزرسانی محصول» اضافه شد.
- مقدار پیش‌فرض این گزینه برای نصب تازه `0` است.
- در حالت خاموش، Mobo Core همچنان transientهای محصول ووکامرس، Object/Post Cache وردپرس و URL دقیق صفحه محصول را پاک می‌کند.
- در حالت روشن، URLهای Shop، دسته محصول، برچسب محصول و صفحه اصلی نیز برای پاک‌سازی هدفمند ارسال می‌شوند.
- فراخوانی‌های broad post purge در WP Rocket، LiteSpeed و W3 Total Cache فقط هنگام فعال بودن پاک‌سازی آرشیو اجرا می‌شوند.
- در WP Super Cache هنگام خاموش بودن گزینه، فیلتر رسمی حذف صفحات مرتبط موقتاً غیرفعال می‌شود تا درخواست Mobo Core به صفحه تغییرکرده محدود بماند.
- نصب تازه دیگر `mobo_core_auto_reconciliation_enabled` را فعال نمی‌کند.
- حتی اگر Option مربوط به Reconciliation هنوز ساخته نشده باشد، fallback آن خاموش است و اجرای خودکار آغاز نمی‌شود.
- Migrationهای قدیمی دیگر Repair کامل Desired State را خودکار Start نمی‌کنند؛ شروع Sync یا Repair باید از مدیر وردپرس یا Portal انجام شود.
- تنظیم ذخیره‌شده سایت‌های موجود بازنویسی نمی‌شود و عملیات از قبل در حال اجرا لغو نمی‌گردد.

### محدوده و ریسک

- افزونه‌های کش ممکن است بر اساس تنظیمات داخلی یا hookهای مستقل خودشان صفحات دیگری را پاک کنند؛ این نسخه فقط درخواست‌های صریح Mobo Core را کنترل می‌کند.
- Repair کوچک عنوان placeholder دسته‌بندی که Migration داخلی و محدود است همچنان می‌تواند اجرا شود؛ این عملیات Sync/Repair کامل محصولات نیست.
- هیچ جدول یا ستون دیتابیس جدیدی لازم نیست. گزینه جدید با WordPress Options API ایجاد می‌شود.
- هیچ Token، Security Code، API Key، ثابت Shared Media یا فایل تنظیم اتصال تغییر نکرده است.

### Shared Media

منطق Shared Media، Alias سایزها، Image Queue و مسیر عادی دانلود در حالت Shared Media خاموش تغییری نکرده‌اند.
